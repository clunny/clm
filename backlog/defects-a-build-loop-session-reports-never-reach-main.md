---
title: "Defects a build-loop session reports never reach main"
kind: bug
components: [plugin]
---

Step: the /clm:build skill tells the build-loop session to report each CLM defect it meets with `clm defect`, and says that, since it opens no pull request of its own, "the loop drafts reported defects with the backlog's other bugs".
What happened: `clm defect` run in the build-loop session wrote each report as an uncommitted file in the main checkout's backlog/. Nothing committed or landed them, so they never reached main. The loop plans from main, so it never drafted them; it reported nothing next and, when stopped, said nothing unsafe was left, while three reports sat untracked in the checkout. One of them was the cause of every failed verify that session.
Expected: a defect the build-loop session reports reaches main (the loop lands it, or the skill gives the session a route to land it), or the loop's end-of-loop summary names reports left uncommitted.
Rule: defect-reports, and the build skill's statement about how its reports get drafted.

Checked on 2026-11-16 (`20261116-defects-a-build-loop`): the fix is code-only and lies in `plugin`, in `plugin/skills/build/SKILL.md`. The loop does what its requirements say. It drafts the bugs `clm triage` groups from `origin/main` (`orchestrator.loop/plan-order`), and it puts in the human's queue only the `dirty` and `unpushed` lines `clm wrap-up` prints (`orchestrator.loop/step-housekeeping`), which by design name no untracked file in a main checkout on `main` (`orchestrator.checkpoint`'s scenario *human's files on main*), so its summary saying the session can end follows `orchestrator.loop/end-summary`. What is wrong is the skill's sentence that the loop drafts reported defects with the backlog's other bugs: it does so only once a report is on `main`, and the skill names no step that puts it there. The route already exists and its rules are written: a branch of the session's own from `origin/main` that only adds the `backlog/` file gates `code` (`gate/backlog-additions`, `small-change-no-claim`) and lands with `clm land <branch>`. The fix names that route in the skill, in place of the false sentence. Having `clm wrap-up` or the loop report a main checkout's untracked items was not taken: it needs a requirement, and is code work outside the plan in `backlog/a-passing-check-proves-less-than-the-spec-claims.md`, whose freeze holds. This supersedes the acceptance in `20261113-a-defect-reported-from`, which held that fixing the skill needed a requirement whose test reads the sentence; the fix of `the-build-loop-prints-a-run-action-again-while-the-same-command` (`d62a4f0a`) since showed that a skill sentence brought into line with written rules needs none.
