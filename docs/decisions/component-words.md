---
title: "What CLM prints and ships says component, ancestors and placeholder component; node stays where it names something else"
date: 2026-11-02
status: accepted
---

`plain-terms-renames` renames node to component, and two more words, the path from the root down to a component and an unbuilt stand-in for one, to ancestors and placeholder component. `20261102-rename-node-to-component` made the keys and flags that hold the word (`component:`, `components:`, `[component_size]`, `--component`, `clm survey --components`) work. This decision says how far the words move in the text CLM prints, writes and ships: the help, the messages and violations, the headings and labels of the views, the web app and the panel, the prompts, the session-start paragraph, the skills and agents, the files `clm init` writes, and the reports CLM files in the backlog.

**The rule.** That text says component, components, ancestors and placeholder component (`Component`, `<COMPONENT>` and so on as the place needs), and never the old words. An old word is `node` or `nodes` in any case, or one of the two other renamed words, standing as a word of its own: with no letter, digit or `_` beside it, and not joined by `-`, `/`, `.` or `:` to more of an ID, a path or a key, nor inside a `{...}` placeholder. A test of each component's text reads it whole (the crate's string literals, its templates, its files under `plugin/`, its help), not only the outputs a requirement quotes. What it keeps it keeps by an allowlist in the test: each entry the exact literal (a JSON key, a CSS class, a hidden flag's attribute, a line `clm affected` prints) and the reason this decision gives for it, plus any line holding `clm:remove-by`. Each component's test holds its own scanner and list, as each owns its own text (`path-ownership`); the scanner is a few lines, and sharing it would make one component's test code every other's dependency.

**What keeps the word**, since it names something else or is not a word to a reader:
- IDs: requirement IDs and slugs (`model/backlog-nodes`), the names of decisions (`node-reconciliation`) and of architectural constraints. A violation names its rule by the requirement's ID, so a requirement whose code prints its ID that way keeps its slug: `apply/create-node`, `apply/remove-node`, `model/node-assets`, `model/parse-node-specs`, `model/optional-nodes` and `check/node-size`. Renaming one would turn every test across the workspace that asserts the rule into a fix of another component's code, and a build of its owner only to change an ID, for a name that already reads plainly; the term swap renames the other slugs, which nothing prints.
- The old keys and flags while they are still read, named as the key or flag they are (`nodes`, `--node`, `node_size`), on a line marked `clm:remove-by`, or in a message that names the old key to say it is old.
- Data fields read by CLM's own programs: the views' JSON (`nodes`, `node`, `pending_nodes`, the blockers' `kind` `node`), the web app's proposal API (`nodes`), and `clm affected`'s `node <id>` lines, which the check command and `clm land` parse. Each is a contract between programs, and renaming one is a change of its own with an expand step (`expand-contract`), not a word swap.
- Things other projects named: Node.js (`Node 24`, `node:fs`), DOM and syntax-tree nodes, GraphQL's `nodes`, CSS classes and HTML attributes that only style or locate an element.
- Code identifiers and comments, which no one but a builder reads (`plain-terms` covers words, not identifiers).

**The old names, spelled out.** `20261102-rename-node-to-component` kept these working beside the new ones until its contract change: the delta key `node` (now `component`), the backlog key `nodes` (now `components`), the setting `node_size` and its table `[node_size]` (now `component_size`), the flags `--node` of `clm defect` and `clm proposals` (now `--component`) and `--nodes` of `clm survey` (now `--components`), and the survey map's key `nodes` (now `components`). Requirement text that describes an old name as still read names it through this decision ("the old key", "the table's old name") rather than spelling it, so the term swap that moves the spec text onto component leaves the description true; a builder takes the literal from this list.

**Not retired.** For these reasons the bare words node and nodes never join `clm/retired-terms`'s list: decision names that keep them are cited by name in specs and `CLAUDE.md`, and `web/src/` imports `node:fs`. The two other words, which name nothing else, are retired once the term swap has moved the spec text. The old keys and flags are retired by their spelled names (`--node`, `--nodes`, `node_size`) in `20261102-rename-node-to-component-contract`.

Rejected:
- **Moving only the outputs a requirement quotes.** The help, prompts and skills would keep saying node in hundreds of places no scenario names, and the retired-terms list could never hold the words.
- **A source scan of the whole workspace from the root.** One test owning every crate's text breaks `path-ownership`: each component's build moves its own text.
- **Renaming the data fields with the words.** The web app and panel would break against a `clm` or Worker one build older, for no reader's benefit.
