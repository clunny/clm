---
title: "The release's bump commit also records its upgrade corpus entry and locks the migrations it ships"
date: 2026-11-05
status: accepted
---

Refines `release-by-dispatch`, whose bump commit held only the version fields. For `upgrades-carry-migrations` a release must freeze what it ships: the project as it sets one up, for the corpus test, and the migrations it carries, so none is edited after a project has taken it (`upgrade-migrations`). Both are generated by `release-prepare.sh` from the bumped tree, in the same bump commit, so they exist exactly when the release does, and are made by the workflow on a human's dispatch, never by hand.

Rejected: building the corpus at test time from git tags. Tests would need the tags and history every clone may not have, and a shallow clone would skip the check that matters most. Rejected too: a pull request after each release adding the entry, which leaves a window in which the latest release has no corpus entry, and can be forgotten.
