---
title: "clm computes and draws the views; the panel and the chat only display them"
date: 2026-10-23
status: accepted
---

The views of the spec graph and the work in flight (`spec`, `flight`, `blockers`) are computed once, by the `view` node, from the spec graph, `clm_check::report` and `queue_from_refs`. `clm view <name>` draws each one in every form a surface needs: a box-drawing chart (plain, or coloured with ANSI), SVG, and JSON. The Claude Code panel and the chat only show what `clm` printed, and the web app draws its own interactive graphs from the same JSON, computed in its Worker by the same crate. Every surface shows the same facts, and every rule about what a view contains is in Rust, where tests prove it (`proven-by-tests`).

The panel is therefore not interactive: selecting a node or expanding a blocker chain is a web feature. An interactive panel can come later, drawn by the panel from `--format json`, without changing what the views contain.

Rejected:
- **The panel draws for itself**, in TypeScript from the JSON, perhaps sharing the web's layout. Interactive, but a second full renderer to keep in step with the web, outside the Rust tests that prove requirements.
- **Text only, no panel.** The cheapest, but no live view and no graphics, which the human asked for.
- **Pictures in the terminal** (kitty, Ghostty, iTerm2 graphics). They don't pass through tmux or other multiplexers and need an SVG rasteriser; a coloured box-drawing chart works in every terminal. Deferred to `backlog/terminal-pictures`.

Updated 2026-10-25 (`20261025-panel-build-rows`): the panel adds, under the chart's node lines, what exists nowhere but in its own Claude Code session: the builds it launched, their nested subagents, and their status, steps, context, tokens, cost and time, read from the hooks events. `clm` can't see a session and the web app has none, so this is the one kind of fact the panel draws itself. Everything derived from git stays `clm`'s, and `view` pins the shape of the node lines the panel matches so a chart change can't break the match silently.

Updated 2026-10-27 (`20261027-terminal-pictures`): the deferred pictures come in, kept to what the rejection above allows. `clm` draws them too: `clm view --format png` is the SVG rasterised with `resvg`, printed as base64 so stdout stays text, compiled only into the CLI, not the wasm build. The pane shows one on the terminal surface only when the person turns picture mode on with its `Picture` button, since the panel can't tell whether the terminal will draw the pixels (kitty, Ghostty, iTerm2, tmux with passthrough) or the `alt` (other terminals, herdr, tmux without it); the coloured box-drawing chart stays the default, and the one every terminal shows. A picture can't take rows between its lines, so with pictures on the Flight tab's build rows follow it, as they follow the SVG elsewhere. Rejected: detecting the terminal from environment variables (`TERM_PROGRAM`, `KITTY_WINDOW_ID`, `TMUX`), which would second-guess the decision Claude Code makes when it draws an `Image` and drift from it; and rasterising in the panel, a second SVG renderer in TypeScript that `clm`'s tests don't reach.

Updated 2026-10-27 (`20261027-interactive-panel`): the panel becomes interactive on the terminal surface without drawing a view itself. It keeps `clm`'s ANSI lines and makes the ones `view` pins pressable: a node's line on the Spec and Flight tabs selects it and opens an inspector over the chart, built from `clm view spec --format json` and `clm view flight --format json` (title, status, owners, dependencies, requirement counts, work in flight); a root's line on the Blockers tab unfolds the chain it holds up, every root starting folded. Lines are matched to the model by position, which `view` pins (`spec-node-lines`, `flight-node-lines`, `blockers-root-lines`), so the panel parses no chart text beyond finding those lines. What the models don't hold (a node's contract, its open changes, its backlog items) stays out of the panel until a model carries it (`backlog/panel-inspector-contract`). The SVG and picture surfaces take no presses, so they draw as before. Rejected: the panel laying out its own tree from the JSON, a second renderer this decision already turned down; and a list of node buttons beside the chart, which repeats every node a second time in a narrow pane.

Updated 2026-10-31 (`20261031-split-view`): picture mode is removed, and `clm view --format png` with it. The human chose to remove it once it was clear nothing but the terminal used it: the `web` Worker links only `clm-view`'s models, with its default features off, and draws its own graphs, and the desktop and web surfaces of the pane draw the SVG. The pictures were for the terminal alone, where the coloured box-drawing chart already shows every fact and is the only form that can be pressed into, so they cost a rasteriser (`resvg`), a font lookup, a second drawing path in the panel and a share of `view`'s size budget for something not needed. The SVG stays, for the pane's desktop and web surfaces. The rejection of pictures in the terminal above stands again, now for this reason.
