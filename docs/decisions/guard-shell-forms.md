---
title: "The guard reads here-strings, option clusters, ANSI-C quotes and quoted substitutions, and bounds its push queries"
date: 2026-10-27
status: accepted
---

Refines `guard-reads-quotes-and-wrappers` and `guard-blocks-push-to-main`. A review of the guard's shell reading found forms no requirement covered (`guard-shell-forms-it-still-misreads`). Each needed a call: catch it, or name it as a known gap of a backstop. The test for each is the one `guard-reads-quotes-and-wrappers` used: is it a form a session writes by accident or habit, and can the token rules read it without becoming a shell parser?

**Caught.**
- *Here-strings fed to a shell* (`bash <<< 'git push origin main'`). The shell runs the word as it runs a heredoc body, and the guard already knows when a segment runs a shell over its standard input (`guard-heredocs`), so judging the word costs one rule (`guard-here-strings`). Fed to anything else, the word stays a redirection's target.
- *Short-option clusters* (`sudo -Eu root git push origin main`). Read as `getopt` reads them: the first letter that takes a value takes the rest of the token, or the next token. The guard already lists each prefix's value-taking options, so this is how it reads them, not new knowledge. With it, `guard-heredocs` names its shell by the segment's command (`guard-command-position`), which the code already did, so `sudo -u root bash <<EOF` is no longer a known gap.
- *`env -S`/`--split-string`*. Its value is `env`'s further arguments in one token; the guard splits it as a segment and reads it in place.
- *ANSI-C quotes* (`$'it\'s'`). Read as the shell reads them: a backslash escapes inside them, so `\'` doesn't close the quote and can't shift the quote state to hide a later segment.
- *`$( )` inside double quotes.* The scan quotes its text as a command of its own up to the matching `)`, so a `"` inside it no longer closes the outer quote. This removes a false positive on the usual commit-message form, `git commit -m "$(cat <<'EOF' ... EOF)"`, whose body's prose (`"a; git push origin main"`) was split into segments and blocked the commit. Once the scan reads the substitution, judging it as commands is what `guard-shell-scripts` already does for a `-c` script, so it closes the `$( )`-inside-double-quotes gap too (`guard-quoted-substitutions`). Backticks inside double quotes keep their gap: their escaping rules differ, and sessions write `$( )`.
- *Push queries with no time limit.* `symbolic-ref`, `config --get-regexp` and `rev-parse @{push}` now share a 20-second budget through `run_within` (`bounded-runs`), which `git-through-layer` made available. With the release lookups' 30 seconds, the guard answers before Claude Code's 60-second hook timeout, which would let the command through. A query that runs out of time blocks the push rather than deciding nothing: a git that never answers is not a git that said "no upstream", and the session has a way out that needs no query, an explicit `HEAD:<branch>`.

**Left as a gap.** A refspec holding a shell expansion (`git push origin $B`, `for b in main; do git push origin $b; done`). Treating it as possibly `main`, as `push-guard` treats a `cd` it can't follow, would block the scripts sessions write to push their own branches (`git push origin "$branch"`), and resolving the variable means interpreting assignments and loops, which is a shell, not a backstop. Pushing `main` through a variable takes setting the variable to `main`, which is not the accident the guard exists for. It joins `eval` and a command held in a variable in the Design's list of what gets through. So do three neighbours the review of this change turned up: a here-string piped into a shell (`cat <<< '...' | bash`), which is `echo '...' | bash` in another spelling; an unmatched `)` inside a quoted substitution, as in a `case` pattern, which ends it early; and a `cd` into a hung directory, whose resolution isn't a git query and so has no budget.

**Alternatives considered.**
- *A real shell parser* (`conch-parser`, tree-sitter-bash), reconsidered as `guard-reads-quotes-and-wrappers` said to if the token rules kept growing. Rejected again: every form here fits the existing scan in a rule each, the parser would still miss expansions and `eval`, and it is a new dependency for a backstop. Reopen if another round of forms needs more than a rule each.
- *Letting a timed-out push query decide nothing*, as a failed one does. Rejected: it reproduces the fail-open the bound exists to remove, only sooner.
- *One budget for push queries and release lookups together.* Rejected: a command with both would let a slow push query starve the release lookup, whose failure blocks, so the release rule would block for the push rule's reason.
