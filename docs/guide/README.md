# CLM guide

CLM is a Claude Code plugin and a `clm` CLI for building software with AI from a spec, solo or as a team. Humans decide what the system should do. AI writes all the code. Programs check that the two agree, and git carries everything between people and sessions.

The guide is also at [clm-app.dev/guide/](https://clm-app.dev/guide/), and `clm guide` prints any page of it in your terminal. Read in this order:

1. [Why CLM](why-clm.md): the philosophy, and the opinions you sign up for.
2. [Quickstart](quickstart.md): install CLM, bring a new or existing project under it, and see your first change built.
3. [Using CLM](using-clm.md): the workflows you run day to day: propose, approve, build, triage.
4. [How it works](how-it-works.md): what the workflows do underneath: the spec, branches, landing, proof and the backlog.
5. [Teams](teams.md): how several people and sessions share one project.
6. [Contributions](contributions.md): taking suggestions and spec changes from people outside the project.
7. [Hackathons](hackathons.md): a small team going from idea to working software in hours.
8. [Shaping the graph](shaping-the-graph.md): how big a component is, when and how to split one, shared layers.
9. [Reference](reference.md): the spec format, decisions, commands.
10. [Glossary](glossary.md): every term CLM uses, in plain words.
11. [FAQ](faq.md): short answers to the questions people ask first, and how CLM compares with other tools.
