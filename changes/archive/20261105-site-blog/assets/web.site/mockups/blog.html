Every requirement has a test that names it, at its version

A requirement counts as built only when a passing test cites it by ID and content-hash version, so rewording the spec marks its tests out of date without anyone having to remember.

8 Nov 2026·7 min read·testing, traceability

Your spec says one thing, your code does another, and nobody can tell you when they parted. With an AI agent writing the code it gets worse: the agent says "done", the tests are green, and you have no way to see which sentence of the spec those tests were written to prove.

The rule

CLM's ARCHITECTURE.md holds the constraint proven-by-tests:

A requirement SHALL count as implemented only when a passing test cites its ID at its current version.
req:<component>/<slug>@<version>
