## Intent

Wave 5 of phase 5 of `backlog/a-passing-check-proves-less-than-the-spec-claims.md`, its branch A of two: `plugin.hooks`, `plugin.hooks.guard` and `plugin.hooks.guard.shell` (crates `clm-hooks` and `clm-guard`) are each brought, in one pass and one delta, to the rule for a requirement (`requirements-state-what-the-contract-shows`), with a small delta of `host` for the other side of a removed requirement. Each requirement now states what the code shows at the boundary: what `clm defect`, `clm hook session-start`, `clm hook autosync` and `clm hook guard` print, how they exit and what they write, and what the guard's shell reading yields to its rules. Scans of source text are cut, and the faults the pass found in the code are mended by each component's build. Branch B, `20261123-wave-5-plugin-by-the-rule`, holds `plugin`, `plugin.agents` and `plugin.panel`; no clause moves between the two branches.

## What the pass found

Read against the rule and the code by one reader per component, then by one drafter per component that checked each entry against the code and probed `clm hook guard`, with a check and a correction round. The builds mend, worst first:

- **The guard lets through commands that push to `main`, cut a release or merge a pull request** (`plugin.hooks.guard.shell`, `plugin.hooks.guard`):
  - a backtick substitution inside double quotes is read as plain text, so ``echo "`git push origin main`"`` exits 0 though the shell runs the push;
  - the `$( )` and backtick substitutions in an unquoted heredoc's body are judged as nothing, though the shell runs them when it sends the body;
  - a `cd` with options (`cd -P m`, `cd -- m`) or a second directory resets the checkout to the event's `cwd`, and a glob is taken literally in a `cd`'s directory, an `env -C` or `sudo -D` value and a `git -C` value (`cd m*`, `env -C m* git push`, `git -C m* push`), so a push from a checkout on `main` is judged from elsewhere;
  - an event with no `cwd` runs no push query (a `git push` is allowed) while a re-run's lookups run in the guard's own directory; every rule now judges such an event from the guard's own working directory, and when that directory is gone too, an absolute `cd`, `env -C`, `sudo -D` or `git -C` is still followed and a re-run's lookups count as failed with no `gh` call;
  - only the first `gh` token of a segment is judged, so `sudo -u gh gh release create v1` and `env -C /src/gh gh release create v1` exit 0;
  - `git --config-env a=B push origin main` reads `a=B` as the subcommand and exits 0;
  - `gh` options before the subcommand hide it (`gh release --notes x create v1`, `gh pr --body x merge 3`, `gh workflow --ref x run release.yml` exit 0);
  - `gh api -X GET -X POST …` counts as a read, while gh sends a POST.
- **A failed write of an ask or a block** (`plugin.hooks.guard`): `clm-guard`'s call returns 1 when it can't write an ask or a block; it now returns 2. The binary does not yet carry that to the hook's caller: a block whose standard error can't be written exits 101, and an ask whose standard output can't be written exits 0, so `clm approve` runs with no prompt. That is the root's, filed as `backlog/clm-hook-guard-lets-a-command-through-when-its-ask-or-block-can-t-be-written`; this change promises only what the call returns, not that the command is refused.
- **The guard blocks what it shouldn't** (`plugin.hooks.guard`): `gh workflow run --ref release ci.yml` is refused as a release run because the guard also judges the third word; the workflow argument is now found as gh reads its options.
- **An ask the agent harness can only refuse says nothing of the rest of the command** (`plugin.hooks.guard`): under Codex or `none`, `git commit -m m && clm approve spec/x` exits 2 without the line that nothing in it ran.
- **The session-start and autosync hooks bypass the streams and environment their call is given** (`plugin.hooks`): the session-start status writes `checkout not compared` and `size not checked` to the process's own standard error, and builds `view.repo`'s budgets by literal; the autosync hook reads `GIT_SSH_COMMAND` from the process, not the call's lookup. They move onto `clm status`'s and `clm autosync`'s own command calls. One visible difference, on standard error only: with settings that don't load, the session-start hook's standard error also gets `size not checked: <why>`; neither Claude Code nor Codex adds a SessionStart hook's standard error to the session on exit 0.
- **Help prints a code comment** (`plugin.hooks`, `plugin.hooks.guard`): `--help` through each crate's command call prints the parser type's doc comment as its first line, not the command's description.
- **Dead public calls** (`plugin.hooks`): `autosync(event)` and `settings(cwd)` have no caller, and `session_start(event)`, `session_start_hook` and `autosync_hook` have only tests; the first three go, the last two become private, and their tests move onto the command calls. The `toml` dev-dependency of both crates goes with the deleted `git_layer.rs` scans.
- **Comments that name what doesn't exist**: `clm-hooks`' `defect.rs` names `model/backlog-nodes` (it is `model/backlog-components`); `clm-guard`'s `lib.rs` names `clm-hooks`' `settings` (removed here) and the decision `approve-in-session` (it is `approval-policy`).
- **Contracts that didn't match the code**: `plugin.hooks`' offered calls only tests use and left out the command calls the root uses; `plugin.hooks.guard.shell`'s named none of the calls the rules read.
- **A Contract sentence and a requirement in conflict** (`plugin.hooks`): `session-status` said a failing status prints nothing, where `session-upgrade-reminder` prints the upgrade line even then; `session-status` now says only the upgrade line is printed.
- **Needs against `depends_on`**: `plugin.hooks/defect-backlog`'s Need on `clm/component-flags`, `plugin.hooks.guard/release-run-lookup`'s on `host/git-through-layer`, and `host/git-through-layer`'s on `plugin.hooks.guard/git-through-layer` and `clm/no-watch-crate` ordered nothing and go.
- **Found and filed, outside this change's requirements**: `clm defect` runs `gh` with the process's environment, not its call's (`backlog/clm-defect-runs-gh-with-the-process-s-environment-not-the-call-s`); `view.repo`'s `status` and `sync`'s `autosync` lose their only caller once `plugin.hooks` is built (`backlog/view-repo-s-status-call-has-no-caller-once-the-session-start-hook-uses-clm-status-s-call`, `backlog/sync-s-autosync-call-has-no-caller-once-the-stop-hook-uses-clm-autosync-s-call`); the guard reads `cd a b` by bash's rule where a zsh session substitutes in the path (`backlog/the-guard-reads-cd-a-b-as-bash-does-where-a-zsh-session-substitutes-in-the-path`, an idea); `plugin.hooks.guard`'s `paths` keep `crates/clm-guard/tests/git_layer.rs` until its build deletes the file, for a later spec change to drop (`backlog/plugin-hooks-guard-s-paths-still-name-a-test-file-its-build-deletes`); `clm hook guard` lets a command through when its ask or block can't be written (`backlog/clm-hook-guard-lets-a-command-through-when-its-ask-or-block-can-t-be-written`, a bug on the root for wave 7).
