## MODIFIED Requirements

### Requirement: fake-github <!-- base: 1a1c6ebdb7f57842 -->
The fake GitHub SHALL answer as GitHub does, where the three crates' tests depend on it, in four respects. It SHALL give a repo's open pull requests to the `Pulls` query (`FakeRepo.pulls` whose `state` is `open`, in their order) in pages of at most the `first` asked, from the `after` cursor, with `pageInfo`'s `hasNextPage` and `endCursor`. In a `Blobs` query it SHALL answer each variable `$e<i>` holding `<rev>:<path>` as the field `f<i>`, a blob's `text`, `isBinary`, `isTruncated` and `oid`, and each variable `$t<j>` holding `<rev>:<dir>`, or `<rev>:` for the top of the tree, as the field `t<j>`, that directory's `entries`, each with its `name` and its `mode` as GitHub's GraphQL gives it, an integer: the octal mode `FakeRepo.modes` holds for the path read as a number, 33188 (`100644`) when it holds none, and 16384 (`040000`) for a directory. `GET /repos/{o}/{r}/pulls?head=<owner>:<branch>` SHALL give each open pull request of `FakeRepo.pulls`, and each page of `FakeRepo.pages`, whose head is `<branch>` of the repository `<owner>` names, with its `number`, `html_url`, `title`, `head`'s `ref`, `sha` and `repo.full_name`, and `base`'s `ref` and `repo.full_name`: a pull request's head repository is the repo itself, or `<FakeRepo.fork_owner>/<repo>` when its `fork` is set (`fork` when `fork_owner` is empty), its base always the repo. When the request also names `base=<base>`, it SHALL give only those of them whose base `ref` is `<base>`, `<base>` percent-decoded as `head=` is; a page's base is `FakeRepo.default_branch`, except that a page whose number is a pull request's of `FakeRepo.pulls` is that pull request and has its base. And the fake SHALL answer 502 to `GET /repos/{o}/{r}/git/blobs/{sha}` for a blob `FakeRepo.blob_fails` names, and to any REST request whose path after `/repos/{o}/{r}/` starts with an entry of `FakeRepo.fail_paths` (as `pulls` or `git/matching-refs/heads/spec/`), leaving every other request as it was. `FakePull`'s fields are unchanged: the knobs are `FakeRepo`'s.

#### Scenario: pages, modes and a failed blob
- GIVEN a fake repo `o/a` with 150 open pull requests, among them #5 from `spec/c` and #6 from a fork's `spec/c2` beside #7 from `o`'s own `spec/c2`; a commit holding `a/link` at mode `120000`, `a/b.md`, `a/c/d.md` and `top.md`; the blob of `a/b.md` in `blob_fails`; and then `fail_paths` holding `pulls`, and then `git/matching-refs/heads/spec/`
- WHEN the `Pulls` query is asked with `first` 100 and then from the first page's `endCursor`; a `Blobs` query asks for `$e0` `<commit>:a/b.md`, `$t0` `<commit>:a` and `$t1` `<commit>:`; the blob API is asked for `a/b.md`'s blob; REST `pulls?head=o:spec/c2` and `pulls?head=o:spec/c` are asked; and, under each `fail_paths`, REST `pulls?head=o:spec/c`, `git/matching-refs/heads/spec/` and the `Pulls` query are asked
- THEN the first page holds 100 with `hasNextPage` true and the second 50 with it false; `f0` is `a/b.md`'s text, `t0`'s entries are `b.md` at 33188, `c` at 16384 and `link` at 40960, and `t1`'s are `a` at 16384 and `top.md` at 33188; the blob API answers 502; `head=o:spec/c2` gives #7 alone, its head and base repository `o/a`, and `head=o:spec/c` gives #5; with `pulls` failing the REST pulls answers 502 while `matching-refs` and the `Pulls` query answer as before; and with `git/matching-refs/heads/spec/` failing that listing answers 502 while both pulls reads answer as before

#### Scenario: the base a listing names
- GIVEN a fake repo `o/a` whose default branch is `main`, with open pull request #8 from `spec/c3` onto `release` and #9 from `spec/c3` onto `main`, and a page #10 for `spec/p`
- WHEN REST `pulls?head=o:spec/c3&base=main`, `pulls?head=o:spec/c3&base=release`, `pulls?head=o:spec/c3`, `pulls?head=o:spec/p&base=main` and `pulls?head=o:spec/p&base=release` are asked
- THEN they give #9 alone, #8 alone, #8 and #9, #10, and none
