# Found by search and agents

## Intent

Make `clm-app.dev` easy to find in web search and, more, in AI search (ChatGPT, Claude, Perplexity), so that CLM is recommended to people asking how to build software with AI from a spec, and easy for agents to read so they can tell someone how to use it. The site gets per-page metadata, a sitemap and `robots.txt`, structured data, an FAQ page written for the questions people ask, and agent files (`llms.txt`, `llms-full.txt`, a Markdown copy of each guide page) made at build time from the guide, so they can't drift. The nav and homepage link to GitHub with the star count. The guide is brought up to date with the specs, and the plugin downloads its binary with `curl` from the public release, so installing CLM no longer needs a signed-in `gh`.

## Problem

The site has one site-wide title and description, no `robots.txt`, sitemap, canonical links, social cards or structured data, and nothing written for agents. Search engines and assistants have little to index or quote, and an agent asked about CLM has to scrape HTML. Nothing on the site answers the questions people put to an assistant ("how is this different from Spec Kit?"), and the GitHub repository, where developers judge a tool, isn't linked from the homepage. The guide has fallen behind the specs in places (backlog kinds, triage's menu, signed repositories, build order), and the quickstart still asks for `gh` signed in, because the plugin's shim downloads with `gh release download`, which the repository going public no longer needs. Its credits leave out Kubernetes, whose controller loop is the idea CLM's reconciliation borrows, and name what CLM took from Anthropic's playbook only vaguely.

## Approaches

- **Machine-readable layer and GitHub link only.** Robots, sitemap, metadata, structured data, agent files, GitHub link. Makes CLM readable, but assistants recommend pages that answer the question asked, and this adds none. Not enough alone.
- **That, plus answer-shaped content in the guide (chosen).** An FAQ page in `docs/guide/` answering what people ask, including how CLM compares with Spec Kit, Kiro and a plain `CLAUDE.md`, with `FAQPage` data made from it; a summary paragraph opening every guide page, which becomes its description. In the guide, so `clm guide` prints it too and nothing is written twice.
- **That, plus off-site work in code.** The repository's description and topics, listings and the operator's posts are outside the repository; they are recorded as the human's tasks instead.
- **Star count:** read at build time (chosen: crawlers see it, visitors' browsers make no request to GitHub, as the site keeps its third parties to one) over a live badge or a client-side API call (a request per visit, invisible to crawlers that don't run script). The count is as old as the last release.
- **Agent files:** generated by the build and never committed (chosen) over committed files kept equal by a check (`regenerate-dont-merge`).
- **Download without `gh`:** `curl` from the public release URL (chosen), keeping the checksum check, over keeping `gh` (needs an account and sign-in for a public file) or `gh` with a `curl` fallback (two paths for one job).

## Outcome

- Every page readable without script, with its own title, description, canonical link and social card; `robots.txt` welcoming every crawler and keeping out only the invite-only app's paths; `sitemap.xml`; `SoftwareApplication` data on the homepage and `FAQPage` data on the FAQ (`site-found-by-search-and-agents`).
- `llms.txt`, `llms-full.txt` and `/guide/<name>.md`, made from `docs/guide/` and `docs/spec-format.md` in the build, compared with their files by tests.
- A GitHub link with the star count in the nav and on the homepage's first screen; the release's deploy passes the workflow token for the count (`ci/web-deploy`).
- The homepage's and `why-clm`'s credits add Kubernetes's controllers, and `why-clm` names what CLM takes from the playbook and where it goes further; `why-clm` also credits OpenSpec, whose conventions the spec format borrows. `README.md` links the site first and credits the same works.
- `plugin/bin/clm` downloads with `curl` (`binary-from-releases`, amended); the quickstart asks for `git` and `curl`, not `gh`.
- The guide is brought up to date: backlog kinds (`human-task`, `workaround`), triage's menu, signed repositories and `docs/allowed_signers`, `needs-alone-order` in place of graph order, `clm init`'s `.gitignore` lines, the `affected` and `target_cap_gb` settings, the gate's `mixed`, the queue's states, `clm contribution`, the public site's address, and a summary paragraph opening every page. The site-analytics change's body loses a retired term that failed the suite on `main`.
- The operator's tasks: Cloudflare's AI-crawler setting, Search Console and Bing, and off-site presence (the repository's metadata, listings, blog and LinkedIn posts).

## Constraints

- `guide-from-docs`: the guide's files stay the one source; every page, copy and structured datum is made from them at build time.
- `site-served-from-assets`: everything added is a static file; no page costs a Worker request.
- `invite-only-web`: `/app/`, `/api/` and `/auth/` stay out of the index.
- `install-repository`: the GitHub link is made from the install repository's one value.
- `yagni`: no per-crawler rules, no live star badge, no second site.
