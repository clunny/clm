The split

You own the what. AI owns the how.

You and your team decide the architecture and the capabilities, with AI helping you think them through. Everything below that line is the AI's: designs, code, tests. You review intent, never diffs.

YouArchitecture: what must always hold.
Capabilities: what people can do with it.
One yes or no on each change that matters.
AITurns intent into a graph of specs.
Builds every node, test-first, in parallel.
Fixes what drifts, defers what's big.
The loop

Reconciliation, borrowed from Kubernetes

CLM isn't a Kubernetes tool. It borrows one idea from it: declare the state you want, and let a controller close the gap, again and again.

KubernetesYou declare the cluster you want. A controller compares it with what's running and acts until they match.
CLMYou declare the system you want. CLM compares it with the code — by content hash, per requirement — and AI builds until every requirement is proven again.
Not a vibe-coded mess

Still maintainable a year from now

Every rule has a testA requirement counts as built only when a passing test cites it at its current version.
Drift can't landChange a requirement and the code behind it is stale until it's rebuilt. Programs check it, not prose.
Nothing deadCode no requirement asks for is removed. The spec describes the present; git keeps the past.
Solo or as a team

Git is the only channel

Specs, claims, approvals and lands are files and branches in your repository. Many sessions — or many people — build at once, each on its own node, each landing through the same checks. No server to run, nothing to keep in sync.
